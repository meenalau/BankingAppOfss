Why table cells need a renderer instead of just a converter attribute

oj-table columns don't accept a converter property directly the way oj-input-text does 
— for formatted cell display, JET expects a renderer function that returns DOM content. 
This is a good distinction to call out to your class: converters on form inputs format live user-editable values,
 while table cell renderers format read-only display values 
— same underlying IntlNumberConverter/IntlDateTimeConverter objects, reused in two different contexts.
